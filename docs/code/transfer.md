# `mars_flight/transfer.py`

## Назначение

Модуль численно интегрирует пассивное движение в гелиоцентрической
системе отсчёта. Физические уравнения, начальные условия и ограничения
приведены в [теории перелёта](../solar_transfer.md).

## Типы и результат

`SolarTransferResult` — контейнер истории расчёта. Поля с массивами
имеют тип `NDArray[np.float64]`: `NDArray` описывает массив NumPy,
`float64` — вещественные элементы двойной точности. `dtype=np.float64`
задаёт фактический тип при создании массива;
`astype(np.float64, copy=False)` приводит к нему массивы `solve_ivp`
без лишней копии, если тип уже совпадает. `@dataclass(frozen=True)`
запрещает переназначение полей контейнера, но не изменение самих массивов.

| Поле | Смысл | Единица |
|---|---|---:|
| `time_s` | время от начала солнечного участка | с |
| `x_m`, `y_m` | гелиоцентрические координаты | м |
| `velocity_x_m_s`, `velocity_y_m_s` | знаковые компоненты скорости | м/с |
| `radius_m` | расстояние до Солнца | м |
| `heliocentric_speed_m_s` | модуль гелиоцентрической скорости | м/с |
| `specific_energy_m2_s2` | удельная энергия в поле Солнца | м²/с² |
| `specific_angular_momentum_m2_s` | знаковая $z$-компонента удельного момента импульса | м²/с |
| `mars_orbit_radius_m` | радиус принятой орбиты Марса | м |

Свойства `duration_s`, `final_radius_m` и
`final_heliocentric_speed_m_s` извлекают последние значения истории.
`final_radial_velocity_m_s` вычисляет проекцию скорости на радиус,
`final_tangential_velocity_m_s` — знаковую касательную компоненту через
удельный момент импульса. `mars_orbit_radius_error_m` возвращает
`final_radius_m - mars_orbit_radius_m`; это знаковая разность радиусов,
а не расстояние до конкретного положения Марса.

## `SolarTransferModel`

Конструктор сохраняет проверенные `MissionParameters` и
`TransferIntegrationParameters`. Метод
`simulate(departure_earth_relative_excess_speed_m_s)` принимает
неотрицательный модуль скорости ухода относительно Земли. Он отвергает
`NaN`, бесконечность, отрицательную скорость и начальную
гелиоцентрическую скорость не ниже солнечной скорости ухода: у такой
орбиты нет нужной противоположной точки ограниченного эллипса.

`_derivatives()` принимает состояние в порядке
`(x, y, velocity_x, velocity_y)` и возвращает производные в том же
порядке. `np.hypot()` вычисляет расстояние или модуль скорости из двух
компонент. Выражения производных даны в
[физической модели](../solar_transfer.md).

## Интегрирование и событие

`solve_ivp(..., method="RK45")` применяет адаптивный метод Рунге — Кутты.
`rtol` задаёт относительный безразмерный допуск; массив `atol` содержит
по два допуска в метрах и метрах в секунду для соответствующих компонент
состояния. `max_step` ограничивает шаг сверху. Настройки берутся из
`config.py`, а не задаются внутри метода.

Вложенная `opposite_side_event()` возвращает координату `y`.
Она определена внутри `simulate()` и передаётся в `solve_ivp` как
функция события. Внешние локальные переменные ей не требуются. Через `setattr()` ей назначаются
`terminal=True` и `direction=-1.0`: интегрирование останавливается
при пересечении оси сверху вниз. Начальное `y=0` не завершает расчёт,
поскольку сразу после старта `y` растёт. Найденное время лежит в
`solution.t_events[0]`.

Если решатель сообщает `success=False` или событие не найдено до
`maximum_time_s`, метод вызывает `RuntimeError`. После успешного
решения из `solution.t` и строк `solution.y` строятся истории
координат и скоростей, затем рассчитываются радиус, модуль скорости,
энергия и момент импульса.
