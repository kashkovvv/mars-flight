# `tests/test_theory.py`

## Назначение

Модуль проверяет входные параметры, геометрию переходной орбиты, направления
скоростей и контрольные значения перелёта Земля — Марс.

## Запуск

```bash
python -m unittest tests.test_theory -v
```

## Проверки

| Проверка | Ожидаемый результат |
|---|---|
| нулевой, отрицательный или бесконечный параметр | `ValueError` |
| радиус орбиты Марса не больше радиуса орбиты Земли | `ValueError` |
| большая полуось перехода | находится между радиусами орбит |
| избыточная скорость ухода | положительна |
| проекция скорости относительно Марса | отрицательна |
| модуль относительной скорости | равен модулю проекции |
| энергия и момент импульса на обеих апсидах | сохраняются |
| переход между системами отсчёта | сумма/разность скоростей даёт гелиоцентрические значения |

Численные тесты сравнивают время перелёта и характерные скорости с
контрольными значениями из
[аналитического расчёта](../hohmann_transfer.md).

Аргумент `delta` в `assertAlmostEqual()` задаёт абсолютную погрешность и
имеет единицу сравниваемой величины. Поэтому для времени используется
`TIME_TOLERANCE_DAYS`, а для скоростей — `SPEED_TOLERANCE_KM_S`. В отличие
от `rtol` численного решателя, `delta` не умножается автоматически на
текущее значение.

## Средства `unittest`

Классы тестов наследуются от `unittest.TestCase`. Каждый метод, имя которого
начинается с `test_`, запускается как отдельный тест.

`assertRaises(ValueError)` проверяет, что внутри блока `with` возникает
ожидаемое исключение. Контекстный менеджер `with` автоматически отмечает
тест как неудачный, если исключение не возникло.

`subTest(value=invalid_value)` создаёт отдельный подписанный случай для
каждого значения цикла. Поэтому при ошибке видно конкретное значение, но
остальные случаи всё равно проверяются.

При запуске через `unittest discover` тесты находит и запускает
тестовый загрузчик; в этом файле нет отдельной точки входа
`unittest.main()`.
