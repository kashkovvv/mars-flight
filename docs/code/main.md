# `mars_flight/__main__.py`

## Назначение

Консольная точка входа последовательно запускает аналитический переход
Гомана, численный взлёт и численный пассивный перелёт. Единицы СИ
преобразуются только для вывода.

## Алгоритм

1. `HohmannTransfer.from_parameters()` определяет требуемую скорость
   ухода относительно Земли и аналитические ориентиры для перелёта.
2. `EarthAscentModel.simulate()` рассчитывает взлёт до этой энергии.
3. Из последнего значения `ascent.specific_energy_m2_s2` вычисляется
   **фактическая** скорость ухода `sqrt(2 * energy)`. Передача
   `ascent.final_radial_velocity_m_s` вместо неё была бы ошибкой:
   корабль ещё находится в земном гравитационном поле.
4. `SolarTransferModel.simulate()` получает скорость ухода относительно
   Земли и сам складывает её с орбитальной скоростью Земли для задания
   гелиоцентрического начального состояния.
5. Выводятся аналитические параметры, результат взлёта и численного
   перелёта. Отрицательная проекция скорости относительно Марса
   обозначает отставание корабля в направлении движения Марса.

Перед переходом к пассивному участку проверяется положительность земной
удельной энергии. Если её нет, `main()` вызывает `RuntimeError`; ошибки
численного интегрирования также не скрываются.

## Смысл вывода

Аналитический блок содержит эталонные скорости и время Гомана.
Численный блок содержит время до противоположной стороны орбиты,
гелиоцентрический радиус и скорость корабля. Последняя строка выводит
**знаковую разность радиусов** корабля и орбиты Марса в этой точке.
Миллиметровое значение для стандартных параметров означает согласие
двух идеализированных расчётов при заданных допусках, а не точность
реального полёта к планете.

Запуск:

```bash
python -m mars_flight
```

Условие `if __name__ == "__main__":` вызывает `main()` при таком запуске;
при импорте модуля расчёт не выполняется.
