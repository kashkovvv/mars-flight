# `mars_flight/__main__.py`

## Назначение

Консольная точка входа создаёт `MissionModel` из стандартных параметров
`config.py` и вызывает `simulate()`. Соединение взлёта, перелёта и посадки,
включая проверки на границах этапов, находится в [`mission.py`](mission.md).
`__main__.py` отвечает за текстовый вывод, создание папки запуска,
сохранение файлов и показ графиков.

## Алгоритм

1. `MissionModel.simulate()` возвращает единый `MissionResult` с аналитическим
   ориентиром, тремя численными результатами и скоростью подлёта к Марсу.
2. Из результата выводятся физические величины. Единицы СИ преобразуются
   только для текста и подписей графиков. Отрицательная аналитическая
   проекция скорости относительно Марса означает отставание корабля по
   направлению движения Марса; в посадку передан неотрицательный модуль.
3. `create_mission_figures()` строит три фигуры по численным историям.
   Для запуска создаётся папка с меткой времени в `results/`, куда
   сохраняются `ascent.png`, `transfer.png`, `landing.png` и
   `parameters.json` с параметрами экземпляра `MissionModel`.
4. В графической среде `plt.show()` открывает фигуры. При backend `Agg`
   изображения только сохраняются. Блок `finally` закрывает фигуры
   через `plt.close()` и при штатном завершении, и при ошибке сохранения.

Ошибки расчёта из `MissionModel` не скрываются: при неуспешном этапе файлы
результатов не создаются.

## Смысл вывода

Аналитический блок содержит эталонные скорости и время Гомана.
Численный блок содержит время до противоположной стороны орбиты,
гелиоцентрический радиус и скорость корабля. Последняя строка выводит
**знаковую разность радиусов** корабля и орбиты Марса в этой точке.
Миллиметровое значение для стандартных параметров означает согласие
двух идеализированных расчётов при заданных допусках, а не точность
реального полёта к планете. Блок посадки выводит модуль скорости
относительно Марса, начальную высоту на границе принятой сферы влияния,
высоту включения двигателя, длительности снижения и торможения,
скорость контакта, остаточную массу и максимальную перегрузку.
Длительности солнечного и марсианского участков нельзя складывать для
получения точного времени миссии: их траектории не сшиты непрерывно.

## Графики и файлы результатов

Создание графиков, их сохранение и вызов `plt.show()` выполняются при каждом
успешном запуске. Окна открываются, если выбран графический backend.
Дополнительные ключи командной строки не нужны. Папка
`results/` исключена из Git. В `parameters.json` записаны дата запуска,
наборы `mission`, `earth_ascent`, `solar_transfer`, `mars_landing` и допуск
стыковки по радиусу из того же экземпляра `MissionModel`, который выполнил
расчёт. Время записи сохраняется с точностью до микросекунды. Эти данные
позволяют связать изображения с конфигурацией конкретного запуска.
Графики отражают значения, полученные из текущих параметров `config.py`;
подробности — в [документации модуля графиков](plots.md).

В среде без графического интерфейса установка `MPLBACKEND=Agg` позволяет
сохранить PNG без окон. При обычном запуске окна остаются открыты до их
закрытия пользователем.

Запуск:

```bash
python -m mars_flight
```

Условие `if __name__ == "__main__":` вызывает `main()` при таком запуске;
при импорте модуля расчёт не выполняется.
